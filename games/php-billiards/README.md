# PHP Billiards

PHP Billiards is a local practice table and Matrix-backed two-player eight-ball game. PHP owns deterministic fixed-step ball physics, casual eight-ball rules, exact checkpoints, canonical table geometry, camera math, SDL input, the native control HUD, and the GLES 3 renderer. The browser bridge sizes the canvas, supplies fullscreen and sound, and forwards validated Matrix room events. The application runs directly from its PHAR and has no Tiled, world-composition, Doom, or WAD dependency. Its session and sixteen balls live in Phonics' ECS, demonstrating that the registry and scheduler work independently of those optional content systems; the ECS references the simulation's authoritative Ball objects without copying or reordering physics state.


Ball contacts use stateless Hertz compression and restitution damping for 170 g phenolic spheres, with Coulomb-limited tangential friction. Free flight is swept; compression uses simultaneous RK4 force evaluations at steps no larger than 1/240,000 s within the existing 60 Hz update. Actual gaps delay the rack's contact wave. Balls remain solid in three dimensions while entering pockets, until their centres reach the sink depth. Settlement includes stored elastic energy.

The browser accelerates this arithmetic synchronously with reusable buffers. PHP retains the authoritative ball objects and exact boundary scheduler. The backend yields before a possible cloth boundary and runs pocket constraints after each accepted microstep. It uses binary64 arithmetic and square roots, receives coefficients and geometry from PHP, and transfers packed doubles without JSON float conversion. Native PHP retains the reference implementation. Unit fixtures and complete-shot browser transcripts compare both paths exactly.

Starting Free Play or choosing New Rack records a fresh 32-byte Web Crypto seed; undo and replay retain that seed. Online racks continue to use the players' agreed seed. Rack offsets are validated as one layout and shrink together if necessary. These changes add no checkpoint or network fields.

The browser bridge claims the shared WebGL2 context with multisample antialiasing before SDL starts, so the PHP scene and native HUD render through the same antialiased framebuffer without supersampling the procedural materials.

Drag on the cloth to point the cue, or use the left stick or arrow/WASD keys; hold Shift or click the left stick for fine aim. Set power with up/down or the power meter, and draw down from the meter to pull the cue back and release to shoot. Drag the spin disc, or use Q/E or the triggers for top and draw and Z/C or the shoulders for side spin; X clears it. Space or A shoots, Backspace or B undoes the shot, putting the cue back on the line it was played along and leaving the camera where it is, and R or Y racks again. Right-drag or the right stick orbits the camera and tilts it as steeply as 80°. The view is framed at a point between the cue ball and the table centre, fitted to the way the camera faces, so the ball stays in sight and as much of the table as fits stays centred; the wheel zooms, and 0 or R3 puts the camera behind the cue. When the balls stop, the next aim starts along the camera's view, so the camera never swings round to find the cue. After a scratch, move the ghost cue ball with the pointer, keys, or stick; illegal spots explain themselves and are never sent online. Escape or Start opens the menu (sound, HUD, fullscreen, controls), H hides the HUD, and ? lists every control. The ? hint stays beside the menu button throughout play, even with the HUD hidden; on a controller it names the Start menu instead.

The HUD is drawn natively in PHP with a signed-distance atlas generated from Barlow Semi Condensed (SIL Open Font License), and the browser bridge plays recorded ball, cushion, and pocket samples. Inside a pocket, strikes against the walls play three recorded knocks chosen by their strength, so a ball rolling around the edge chatters audibly and differently each time. Once its top drops below the cloth it is out of sight, and only a real strike knocks there, softly and at most every 90 ms. Reaching the bottom lands with the strongest knock, plus a weaker bounce after a lively entry, just before the sink recording. Balls in the same pocket reach the bottom one at a time, 200-300 ms apart, as if through the narrow neck below the liner.

The title menu offers **Free Play** and **Online Play**. Lobby chat and challenge links use standard Matrix text messages so other Matrix clients remain part of the conversation. Online tables use commit/reveal seeding and explicit sequenced Matrix relations; both players must acknowledge the same exact state hash before another action begins. The exact PHAR, runtime-manifest fingerprint, and rules version must match. See [the online protocol and determinism notes](docs/online.md).

To reproduce the physics checks, run `npm test` and `npm run test:browser`. `php games/php-billiards/benchmarks/breaks.php` checks 64 seeds, five aim offsets, and three powers; `--quick` repeats the original 24-seed diagnostic. Pot counts are observations, not acceptance targets. After building the runtime, `node games/php-billiards/benchmarks/browser.mjs` measures complete physics steps and aim-preview slices. Run performance profiles alone. Add `--quick --exact`, `--reference`, or `--firefox` to compare complete shot states and events. `PHP_SDL_ROOT` can point to an existing runtime directory. Browser CI pins transcript digests for the reference break, four seeded shots, and crowded-pocket congestion.
